## 🏥 Fin-Eye Comprehensive Health Check

### 🔴 Critical Issues (Breaking)

**1. ML Model Registry Path Mismatch**
The `ml_pipeline.py` uses a hardcoded path for its registry:
```python
ARTIFACT_DIR = os.path.join(os.path.dirname(__file__), "..", "..", "data", "models")
REGISTRY_FILE = os.path.join(ARTIFACT_DIR, "model_registry.jsonl")
```
This writes artifacts to `backend/data/models/` — but `technical_service.py` reads from `REGISTRY_FILE` (same path), so that part is internally consistent. **However**, `model_artifacts.py` and `technical_training.py` write to `model_store/artifacts/<SYMBOL>/<TF>/`, and `model_registry.py` writes to `model_store/registry.jsonl`. These are **two completely separate registries** that never talk to each other. `technical_service.py` reads only from the `ml_pipeline.py` registry, so any models trained via the `train_all_models_for_timeframe()` path are **invisible** to the inference engine.

**2. Only AAPL 1h/4h Are Trained — 16 Symbols × 4 Timeframes = Empty**
The `registry.jsonl` has only 2 entries (AAPL 1h, AAPL 4h). The `technical_service.py` expects models for `["1h", "1d", "1wk", "1mo"]` per symbol. For any symbol other than AAPL, `compute_technical_consensus()` throws and falls back to a hardcoded 50.0 neutral score — **which is exactly why the dashboard shows neutral/empty technical data**.

**3. GAS Score Is Showing Fallback Values**
The GAS score pipeline: `gas_precompute` → `_compute_technical_score()` → `compute_technical_consensus()` → fails for missing models → returns 50.0 fallback. Similarly `_compute_sentiment_score()` returns 50.0 if no sentiment rows exist in DB. `_compute_macro_score()` returns 50.0 if no macro indicators are in DB. So GAS = `50*0.4 + 50*0.3 + 50*0.3` = **50.0 for everything** — completely flat, static-looking data.

**4. `technical_service.py` Uses Timeframes `["1h", "1d", "1wk", "1mo"]` But Models Only Exist for `1h` and `4h`**
There's a mismatch — training ran `1h` and `4h` but inference tries `1h`, `1d`, `1wk`, `1mo`. Even for AAPL, the `1d`, `1wk`, `1mo` models are missing so only the `1h` signal works.
